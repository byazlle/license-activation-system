## 1. 架构总览

### 1.1 一句话架构

无框架、零 Composer 依赖的单入口 PHP 应用，PDO 直连 MySQL，全部业务能力以"路由 → 控制器 → 服务 → 仓储"四层组织；密码学能力基于 PHP 内置 `openssl` 扩展，采用"RSA 混合加密"实现两层的"私钥加密 / 公钥解密"；静态资源与业务代码同仓，纯 FTP 部署。

### 1.2 架构决策清单（前置）

| 决策项 | 结论 | 理由 |
|---|---|---|
| PHP 版本基线 | 兼容 7.2，向上兼容 8.x | 用户主机未购买，按最低版本保守设计 |
| 框架 | 不使用 Composer / 主流框架 | 虚拟主机无 SSH，纯 FTP 部署；框架依赖无法落地 |
| 数据库访问 | PDO 预处理，全部参数绑定 | 防 SQL 注入，兼容 5.6/5.7 |
| 密码学 | `openssl` 扩展 + RSA 混合加密 | 满足"私钥加密公钥解密"且规避 RSA 明文长度限制 |
| 密钥体系 | 全局一对 A + 每软件一对 B_i；公钥 A 内置软件，公钥 B_i 随 K 码下发 | 软件只需内置一把通用公钥；按软件隔离，轮换 B_i 只需重发该软件 K 码 |
| 传输 | 当前按 HTTP 部署，不依赖 HTTPS | 内部测试使用；如需生产环境可自行加 HTTPS |
| 可观测性 | 结构化文件日志 + 统一错误码 | 尽力而为的增强，便于排查，不阻塞发卡主流程 |
| 错误处理 | 全局异常捕获，客户端只见友好错误码 | 客户端只见错误码，避免回显堆栈/路径 |
| 部署 | 单入口 + 配置外置 + 安装锁 | 适配虚拟主机，防重装覆盖 |
| 会话 | 原生 session + 文件存储（可切 DB） | 无 Redis 依赖 |

> 关于高并发：本系统为后台管理 + 低频激活请求，虚拟主机场景下**不引入队列、读写分离、Redis**；扣次一致性靠数据库原子 UPDATE + 事务 + 唯一索引保证（见 §8）。若后续量级上升，演进路径见 §12。

## 2. 技术选型与版本基线

### 2.1 运行环境

| 组件 | 目标版本 | 说明 |
|---|---|---|
| PHP | 7.2 ~ 8.3 | 最低 7.2。不使用 7.3+ 语法（如 `array_key_first` 的滥用注意、flexible heredoc、尾随逗号等）；不使用类型化属性（7.4+）、联合类型（8.0+）、`match`（8.0+）、nullsafe（8.0+）、枚举（8.1+） |
| MySQL | 5.6 / 5.7 | 不使用 JSON 字段类型、生成列、窗口函数；用 `TEXT` 存 JSON 字符串 |
| Web 服务器 | Apache（虚拟主机常见）/ Nginx | 均通过 PATH_INFO 或 rewrite 到单入口 |
| HTTP / HTTPS | 当前按 HTTP 部署 | 内部测试环境，无 HTTPS / 无 SSL；如需生产环境可自行加 HTTPS |

### 2.2 必需扩展

| 扩展 | 用途 | 缺失后果 |
|---|---|---|
| `openssl` | RSA/AES 加解密、随机数 | 核心功能不可用，必须 |
| `pdo_mysql` | 数据库访问 | 核心功能不可用，必须 |
| `json` | 业务包序列化 | 核心功能不可用，必须 |
| `mbstring` | 多字节处理（中文配置） | 建议，缺可用 `iconv` 降级 |
| `session` | 管理员登录态 | 核心功能不可用，必须 |

> 购买主机前请先确认上述扩展。多数廉价虚拟主机默认开启这些扩展；若 `openssl` 被禁用，只能换主机或升级云服务器。

### 2.3 PHP 7.2 兼容编码约定

- 类型声明：参数和返回值可用 `string/int/array/bool/callable/iterable` 与类名；**不用** `mixed`（8.0+）、`static` 返回类型（8.0+）、联合类型、`?` 之外的可空写法。
- 属性类型：**不写**类型化属性，用 `/** @var string */` 注解代替。
- 数组解构、箭头函数（`fn`）、`??=` 等 7.4+ 特性禁用。
- `str_contains` / `str_starts_with` 等 8.0+ 函数禁用，统一封装到 `Util::strContains()` 等辅助方法。
- 常量可见性（8.1+）禁用。
- 所有依赖通过 `require_once` 手工加载（自建极简 PSR-4 风格自动加载器）。

### 2.4 MySQL 5.6 兼容约定

- 字符集统一 `utf8mb4` / `utf8mb4_general_ci`；索引列长度 ≤ 191（避免 767 字节索引限制）。
- 时间字段用 `INT UNSIGNED` 存 Unix 时间戳（避开 5.6 多 TIMESTAMP 列限制与时区问题）。
- JSON 数据存 `TEXT`，由应用层 `json_encode/decode`，不依赖数据库 JSON 函数。
- 每张表显式 `ENGINE=InnoDB`（事务与行锁需要）。

## 3. 部署拓扑

### 3.1 虚拟主机方案（推荐起步）

```
[用户浏览器] --HTTP--> [虚拟主机: Apache + PHP 7.2]
                              |
                              | PDO
                              v
                        [MySQL 5.6/5.7 同主机或独立]

目录布局（Web 根目录 public/ 之外的敏感文件不可通过 HTTP 访问）：
project/
├── public/                # Web 根，唯一对外目录
│   ├── index.php          # 单入口
│   ├── .htaccess          # rewrite 到 index.php；禁止目录列表
│   └── assets/            # CSS/JS（静态）
├── app/                   # 业务代码（Web 根之外）
├── config/                # 配置文件（Web 根之外）
├── storage/               # 日志、会话（Web 根之外，可写）
├── keys/                  # 全局私钥 A + 每软件一个私钥 B_i（Web 根之外，权限 0600）
└── install/               # 安装器（装完锁定/移除）
```

**关键要求**：虚拟主机的"文档根目录"必须能指向 `public/`，或至少允许把 `keys/`、`config/`、`app/` 放到文档根之外。若主机强制整站都在 Web 根下，则必须用 `.htaccess` 拒绝这些目录的 HTTP 访问，并把私钥放在 `.htaccess` 保护且文件名随机的目录中（安全性下降，建议改云服务器）。

### 3.2 轻量云服务器方案（升级路径）

当出现以下任一情况时切换：`openssl` 被禁 / 无法外置私钥 / 需要定时任务或 AI 代理 / 请求量显著上升。拓扑：Nginx + PHP-FPM + MySQL，私钥放 `/etc/xxx/keys`，配置放环境变量或 Web 根外，日志交 logrotate。如需 HTTPS，也可在云服务器阶段自行配置证书。

### 3.3 决策流程

```
购买主机前确认：
  1. PHP 版本 >= 7.2 且 openssl/pdo_mysql 是否可用？ 否 -> 换主机/云服务器
  2. 是否支持修改文档根到 public/ 或用 .htaccess？ 否 -> 云服务器
  3. MySQL 版本 >= 5.6？          否 -> 云服务器
  全部满足 -> 虚拟主机即可（推荐起步，按 HTTP 部署）
```

## 5. 密码学体系设计（核心）

### 5.1 密钥清单与管理（全局 A + 每软件 B_i）

| 密钥 | 范围 | 用途 | 位置 | 是否下发 |
|---|---|---|---|---|
| 私钥 A | 全局唯一 | 签发 / 重签 K 码（含地址转换） | `keys/private_a.pem`，0600 | 否 |
| 公钥 A | 全局唯一 | 软件离线解 K 码，得 `card_id` + 地址 + 公钥 B_i | `keys/public_a.pem` | 是（内置于所有软件） |
| 私钥 B_i | 每个软件一对 | 加密该软件的业务包 | `keys/private_b_{software_id}.pem`，0600 | 否 |
| 公钥 B_i | 每个软件一对 | 解密该软件的业务包 | 存于 `lc_softwares.public_b`（PEM 文本） | 是（随该软件 K 码下发，软件不预置） |

- 密钥对由 `openssl_pkey_new()` 生成（RSA 2048 位），2048 足够且兼容 PHP 7.2。**全局 A 在安装阶段生成一次；每个 B_i 在创建该软件时自动生成。**
- 私钥严禁写入数据库、日志、配置或任何可被 HTTP 访问的目录；生成后即落盘到 `keys/` 并 `chmod 0600`。
- 公钥 B_i 以 PEM 文本入库（`lc_softwares.public_b`），发卡时取出写入 K 码载荷 `b` 字段；软件端**只内置公钥 A**，第二层公钥 B_i 从 K 码中动态取出，无需为每款软件预置或随软件更新。
- **隔离与轮换**：某软件的 B_i 泄露不牵连其他软件；轮换 B_i 时只需重新生成该软件密钥对并**重发该软件的 K 码**即可，软件内置公钥 A 不用动。全局私钥 A 轮换则会导致全部已发 K 码失效，需全部重签。

### 5.2 为什么必须用"混合加密"

`openssl_private_encrypt()` 在 PKCS#1 v1.5 填充下，单次可加密的明文长度 ≤ 密钥字节数 − 11（2048 位 = 256 − 11 = 245 字节）。业务包含 API Key、JSON 参数，可能超过该长度，因此采用混合加密：

- **RSA 只加密一个随机 AES-256 密钥**（32 字节，远小于上限）。
- **AES-256-GCM**（不支持时降级 AES-256-CBC + HMAC）加密实际数据，长度不限且带完整性校验。

> 注意方向：RSA 用**私钥加密 / 公钥解密**（满足用户"私钥加密公钥解密"要求）；AES 用同一随机密钥加解密。GCM 提供认证标签，防篡改；CBC 降级时必须带 HMAC-SHA256 否则有填充预言风险。

### 5.3 数据格式定义

#### 5.3.1 K 码（第一层）

明文载荷（JSON，尽量短）：

```json
{"v":1,"c":"CARD202611170001","u":"http://license.example.com/api","b":"-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n","s":"demo-app","x":"<16位随机串>"}
```

- `v`：格式版本；`c`：card_id；`u`：授权服务器 Base URL；`b`：**该软件公钥 B_i 的原始 PEM 文本**（不是 base64，JSON 内换行转义为 `\n`，供软件第二层解密业务包）；`s`：软件标识（客户端可直接用它填 `software_id`，无需内置）；`x`：随机校验串。
- 公钥 B_i 约 400–500 字节，但它位于 AES 加密的载荷内（长度不限）；RSA 段始终只加密 32 字节 AES 密钥，不受 RSA 明文长度限制影响。

封装（`||` 表示二进制拼接，最终整体 base64url）。**注意是带长度前缀的变长结构，不是定长**：

```
K码 = base64url(
        algo(1B) || keyLen(2B,大端) || RSA_privA_enc(aesKey)
      || ivLen(1B) || iv
      || tagLen(1B) || tag
      || AES密文
      )
algo=1: AES-256-GCM,  iv 12B, tag 16B（认证标签）
algo=2: AES-256-CBC,  iv 16B, tag 32B（HMAC-SHA256(iv||密文)）
```

- 客户端必须按 `keyLen`/`ivLen`/`tagLen` 逐段解析；`keyLen` 随 RSA 位数变化（2048 位 = 256 字节，3072 位 = 384），不能写死偏移。
- 软件端：base64url 解码 → `openssl_public_decrypt` 用内置**全局公钥 A** 解出 aesKey → AES 解密得到 `c`、`u`、`b`、`s`。
- 服务器地址转换：`CardService` 持有**全局私钥 A**，能完整解包 → 保留 `c`、`b`、`s` 不变、只替换 `u` → 用同私钥 A 重新加密生成新码。

#### 5.3.2 业务包（第二层）

明文载荷：

```json
{
  "v": 1,
  "c": "CARD202611170001",
  "auth": {"type":"times","remain":9,"total":10,"expire_at":0},
  "config": {
    "ai": {"endpoint":"https://api.xxx/v1/chat","key":"sk-xxx","model":"gpt-4o-mini"},
    "text": "任意自定义文本",
    "json": {"temperature":0.7,"system":"..."}
  },
  "ts": 1731000000,
  "n": "<本次请求 nonce 的 sha256>"
}
```

封装与 K 码同构（同一套带长度前缀的二进制布局），只是改用**该软件私钥 B_i 加密、从 K 码解出的公钥 B_i 解密**。

- 软件带 `card_id + 软件标识 + 设备标识 + nonce + 时间戳` 请求；服务器校验通过后查卡识别所属软件，用该软件**私钥 B_i** 加密业务包返回；软件用 K 码中解出的**公钥 B_i** 解密。
- `device_id` 仅记录首次请求设备用于排查，**不做绑定校验**。

### 5.4 加密方向说明

- 用户要求的"私钥加密、公钥解密"已按 §5.3 实现（RSA 部分为私加公解），用于来源认证、防篡改以及传输/存储无明文。
- 公钥 A 内置软件、公钥 B_i 随 K 码下发，均为公开信息；本方案提供的是轻量级保护，不针对逆向者提供强机密性。软件解密后内存中的明文属客户端安全范畴，不在本系统范围（详见 D1 §11.3）。

### 5.5 防重放（源码实际实现）

客户端请求体只需带 `card_id / software_id / device_id / nonce / timestamp`，**没有请求签名**（v1.1 文档写的 `HMAC_SHA256` 签名并未实现，且软件无法安全持有共享密钥）。

服务端校验两条：

1. `|now − timestamp| ≤ 300`，超窗返回 `1002`；
2. `sha256(card_id + "|" + nonce)` 未被使用过（`lc_request_logs.nonce` 唯一索引），重复返回 `1002`。

**注意**：源码中**未实现**频率限制。如线上需要，请在 Nginx 层 `limit_req` 或前置 CDN 处理。

## 6. 关键流程

### 6.1 发卡流程

```
管理员选择软件 → 填模式(时效/次数)+参数 → 生成 card_id
  → CardService 取出该软件公钥 B_i（softwares.public_b）
  → 组装 K码明文(v, card_id, 当前授权地址, 公钥B_i, 软件标识, 随机串x)
  → Crypto 用全局私钥A 混合加密 → K码字符串
  → 入库(cards) + 输出K码
```

### 6.2 时效型激活

```
软件: 内置公钥A 解 K码 -> card_id, url, 公钥B_i, 软件标识
软件: POST /api/activate {card_id, software_id, device_id, nonce, ts}
服务: 校验软件标识 -> 查卡 -> 启用? -> 模式=time? -> now<=expire_at?
      模式不是 time 直接返回 2003（次数卡不能用此接口）
通过 -> LicenseService 组装业务包(含 auth.expire_at, config) -> 用该软件私钥B_i加密 -> 返回
软件: 用K码解出的公钥B_i 解密 -> 得授权与配置 -> 本地直连AI
```

> 次数型卡读配置请用 `POST /api/status`（只读、不扣次），不要用 `activate`。

### 6.3 次数型消费（扣次）

```
软件: POST /api/ticket {card_id, software_id, device_id, nonce, ts}
服务: 事务开始
      UPDATE cards SET remain=remain-1, used=used+1
        WHERE card_id=? AND software_id=? AND status=1 AND mode='times' AND remain>0
      检查 affected_rows == 1，否则回滚并返回 2005
      签发票据(tickets: card_id, ticket, expire_at=now+1800)
      写日志(before, after)
      事务提交
      返回票据 + 用该软件私钥B_i加密的业务包
软件: 用K码解出的公钥B_i 解密 -> 授权(remain)与配置 -> 本地直连AI
说明: 不代理AI流量；扣次点由客户端决定（建议一次用户点击扣一次）
```

### 6.4 次数退回（可选，AI 失败/取消时）

```
软件: AI 调用失败或用户取消
软件: POST /api/refund {card_id, software_id, device_id, nonce, ts, ticket}
服务: 事务开始
      UPDATE tickets SET used_at=now
        WHERE ticket=? AND card_id=? AND used_at=0 AND expire_at>=now
      affected!=1 -> 回滚返回 2006（重复退/已超期）
      UPDATE cards SET remain=remain+1, used=used-1
        WHERE card_id=? AND software_id=? AND status=1 AND mode='times'
          AND remain<total_times
      写日志(action=refund, before, after)
      事务提交 -> 返回 {remain}
说明: 一张票据只能退一次；remain 不会超过 total_times，防止刷次数
```

### 6.5 地址转换流程

```
管理员打开 /convert -> 填新服务器地址(存入 config)
输入旧K码 -> ConvertService:
  1. base64url 解码 -> 全局私钥A 解 aesKey -> AES-GCM 解出 payload
  2. 校验签名/格式(nonce 存在、v 正确)；失败则报错
  3. payload.u = 新地址；保留 card_id 与公钥 B_i（payload.b）不变；重新生成 nonce
  4. 全局私钥A 重新混合加密 -> 输出新K码
  5. 写转换日志(旧地址->新地址, 操作人, 时间)
用户拿新K码 -> 软件公钥A 解出 card_id 与公钥 B_i 不变, u=新地址 -> 走新服务器
```

关键：`card_id` 与公钥 B_i 不变，卡的授权数据留在数据库（随服务器迁移一并迁移），软件无需重发布。

### 6.6 管理后台

标准 CRUD：登录 → 会话 + CSRF → 各控制器 → 服务 → 仓储。所有写操作记录管理员操作日志。

### 6.7 开放 API（AI / 第三方调用）

```
AI / 第三方
   │  POST /openapi/<资源>/<操作>
   │  Authorization: Bearer lsk_xxx
   ▼
Router（CORS + OPTIONS 204 + 三级路径解析）
   ▼
OpenApiController::auth()
   ├─ ApiKeyService::verify()  → SHA256 查表、状态/过期校验
   ├─ ApiKeyService::allows()  → scope 精确匹配 / "*" / "software:*" 前缀通配
   └─ register_shutdown_function → ApiKeyRepo::logCall()（成功失败都记）
   ▼
复用 SoftwareService / CardService / LicenseService / Repo
   ▼
Response::json() 统一 {code,msg,request_id,data}
```

- 密钥明文只出现在创建响应；库里只存 `key_hash` 与 `key_prefix`。
- 老站点首次访问时 `ApiKeyRepo::ensureTables()` 自动补建 `api_keys` / `api_call_logs`，无需单独迁移。
- 管理员页面与开放 API 共用业务逻辑，避免两套行为漂移；写操作记入 `admin_logs`，调用本身记入 `api_call_logs`。
- 接口清单、scope 表、错误码 4001~4005 见 D5。

## 7. 可观测性与错误处理（尽力而为的增强）

### 7.1 统一错误码

| 码 | 含义 | 客户端可见文案 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 参数缺失/格式错误 | 请求参数不合法 |
| 1002 | 请求超时/重放 | 请求已过期，请重试 |
| 2001 | 卡不存在 | 激活码无效 |
| 2002 | 卡已禁用 | 激活码已被停用 |
| 2003 | 模式不匹配 | 授权类型不符 |
| 2004 | 已过期（时效型） | 激活码已过期 |
| 2005 | 次数耗尽（次数型） | 可用次数已用完 |
| 2006 | 票据无效/已核销/已超期 | 无法退回次数 |
| 3001 | K码格式/校验失败（后台地址转换页、开放 API 的解析/转换） | 激活码格式错误 |
| 3002 | 软件标识无效 | 软件未授权 |
| 4001 | 缺少 API 密钥（开放 API） | 缺少 API 密钥 |
| 4002 | API 密钥无效 | API 密钥无效 |
| 4003 | API 密钥已撤销 | API 密钥已撤销 |
| 4004 | API 密钥已过期 | API 密钥已过期 |
| 4005 | API 密钥权限不足 | 密钥权限不足 |
| 9001 | 系统内部错误 | 服务暂时不可用 |

- 服务端日志记录真实异常（含堆栈），**客户端只收到错误码与友好文案**，禁止回显异常消息、SQL、路径。

### 7.2 结构化日志

- 格式：`时间 | level | request_id | 模块 | 事件 | 关键字段(kv JSON)`，写入 `storage/logs/YYYY-MM-DD.log`。
- 关键事件：`activate`、`ticket`、`deduct`、`convert`、`admin_login`、`admin_action`、`error`。
- 同时把激活/扣次记录写入数据库 `request_logs`（详见 D3），供后台统计。
- `request_id` 每次请求生成，贯穿日志与响应头，便于排查。

### 7.3 监控指标（尽力而为的增强）

- 若环境支持，后台"概览"页展示：今日请求数、成功/失败数、扣次总数、失败原因 Top5、日志表大小。
- 统计为尽力而为的增强功能，核心是发卡与激活；若环境不具备统计条件，可仅保留请求日志，不影响主流程。
- 云服务器阶段可选接入邮件告警（失败率突增、日志表过大）。

## 8. 并发与可靠性

### 8.1 扣次一致性（核心）

- 使用单条原子 UPDATE：`UPDATE cards SET remain=remain-1, used=used+1 WHERE id=? AND status=1 AND mode='times' AND remain>0`；以 `affected_rows===1` 判定成功，天然防超扣。
- 该 UPDATE 与票据写入、日志写入置于同一事务；任一步失败则回滚。
- 不采用"先查再改"，避免竞态。

### 8.2 幂等与防重放

- `nonce` 唯一索引（或 `request_logs.nonce` 唯一），重复请求直接拒绝。
- 时间戳窗口 300 秒。
- 票据一次性：核销字段 `used_at`，防止重复使用。

### 8.3 事务边界

- 发卡批量生成：单事务批量插入，失败整体回滚。
- 安装建表：逐表执行，失败记录已完成表并提示，避免半装状态被误判为已装。

## 9. 功能防护（简要）

> 当前按 HTTP 部署（内部测试使用），如需生产环境可自行加 HTTPS。此处仅列必要的功能性防护，不展开安全警告。

| 面 | 措施 |
|---|---|
| 传输 | 当前按 HTTP 部署；客户端请求带 nonce + 时间戳防重放，业务包加密传输 |
| 存储 | 密码 `password_hash`（bcrypt）；私钥 Web 根外 + 0600；配置外置 |
| 注入 | PDO 预处理；表名/列名白名单，禁止外部拼接 |
| XSS | 输出统一 `htmlspecialchars`；模板默认转义 |
| CSRF | 管理后台表单令牌，会话校验 |
| 越权 | 控制器前置鉴权；普通管理员不可操作管理员账号与密钥 |
| 会话 | 空闲超时；登录失败**未做**锁定，建议在 Nginx 层限制 `/admin/login` 频率 |
| 文件 | 禁止上传；`.htaccess` 拒绝访问 `config/`、`keys/`、`storage/`、`app/` |
| 安装 | 装完生成 `install.lock` 并强制校验，入口失效 |
| 限流 | **源码未内置**频率限制；如需要请在 Nginx `limit_req` 或前置 CDN 实现 |

## 10. 关键设计决策与权衡（ADR 摘要）

| ADR | 决策 | 权衡与理由 |
|---|---|---|
| ADR-01 | 零框架零 Composer | 牺牲开发效率换虚拟主机可部署性；用户硬约束 |
| ADR-02 | 私钥加密公钥解密 + 两级密钥 | 全局一对 A；每软件一对 B_i，公钥 B_i 随 K 码下发、软件只内置公钥 A；按软件隔离，泄露不牵连其他，轮换 B_i 只需重发该软件 K 码；接受"非强机密性"边界（D1 §11.3） |
| ADR-03 | API Key 下发 + 直连 | 用户决策；以 Key 额度上限兜底，卡控制仅约束正常用户 |
| ADR-04 | 扣次前置到票据 | 直连模式下无法精确感知 AI 调用，取近似方案；票据 30 分钟有效并支持 `/api/refund` 退回，兼顾用户体验 |
| ADR-05 | 时间戳用 INT | 兼容 MySQL 5.6 且规避时区；展示层格式化 |
| ADR-06 | 混合加密 | 规避 RSA 明文长度限制（RSA 只加密 32 字节 AES 密钥）并获完整性校验 |
| ADR-07 | 虚拟主机起步、按 HTTP 部署 | 成本低；如需 HTTPS 可自行加；不满足扩展条件时按 §3.3 切云服务器 |
| ADR-08 | 统计为尽力而为增强 | 发卡/激活为核心；环境不具备时仅保留日志，不阻塞主流程 |
| ADR-09 | 客户端 API 开放 CORS（`*`） | 便于网页 / WebView / Electron 跨域直连；客户端 API 不使用 Cookie，无凭证泄露面；后台页面仍是同源访问，不受影响 |
| ADR-10 | 票据有效期 1800 秒 | 票据不参与鉴权，仅作统计与退次凭证；60 秒过短，AI 长任务失败后无法退回 |

## 13. 交付与部署要点

1. 购买主机前按 §3.3 逐项确认，避免买错。
2. 上传代码，文档根指向 `public/`，`config/` 与 `keys/` 置于 Web 根外。
3. 访问 `/install`，填 DB、测试连接、建表、建管理员、**生成全局密钥对 A 并下载公钥 A 内置到软件**（各软件公钥 B_i 在创建该软件时自动生成、随 K 码下发，无需内置）。
4. 装完确认 `install.lock` 生成，`install/` 入口失效。
5. 设置 `keys/` 权限 0600（当前按 HTTP 部署；如需生产环境可自行加 HTTPS）。
6. 用 D4 的接口做一次端到端联调（创建软件 → 发卡 → 激活 → 扣次 → 解密 → 转换）。
7. 上线前核对 D1 §12 验收标准全部通过。
