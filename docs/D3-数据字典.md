## 1. 通用约定

1. **存储引擎**：全部 `InnoDB`，使用事务与行锁。
2. **字符集**：`utf8mb4`，排序规则 `utf8mb4_general_ci`。
3. **索引长度**：MySQL 5.6 在 `utf8mb4` 下单列索引上限 767 字节，故所有参与索引的字符串列长度 ≤ 191；更长的唯一串（如 nonce）用 `CHAR(64)` 存哈希值。
4. **时间字段**：统一 `INT UNSIGNED NOT NULL` 存 Unix 时间戳（秒），`0` 表示"无/未设置"，规避 MySQL 5.6 多 `TIMESTAMP` 列限制与时区问题。展示层格式化。
5. **主键**：统一 `id BIGINT UNSIGNED AUTO_INCREMENT`。
6. **软删除**：一般不物理删除，用 `status` 字段标记；日志表除外（按时间归档清理）。
7. **表前缀**：安装时可配置（默认 `lc_`），下文建表语句以 `lc_` 为例。
8. **JSON 数据**：存 `TEXT`，内容为 `json_encode` 字符串，应用层解析，不依赖数据库 JSON 函数。

### 3.2 软件表 `lc_softwares`

| 字段 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT UNSIGNED | 否 | 自增 | 主键 |
| `name` | VARCHAR(128) | 否 | — | 软件名称 |
| `identifier` | VARCHAR(64) | 否 | — | 软件唯一标识，客户端上报，唯一 |
| `default_mode` | VARCHAR(16) | 否 | `time` | 默认授权模式：`time` 时效 / `times` 次数 |
| `default_days` | INT UNSIGNED | 否 | 30 | 时效型默认天数 |
| `default_times` | INT UNSIGNED | 否 | 100 | 次数型默认次数 |
| `default_config` | TEXT | 是 | NULL | 默认配置 JSON（AI/text/json，明文存于库，下发时整体加密） |
| `b_key_id` | VARCHAR(64) | 否 | — | 该软件 B_i 密钥标识（如 `b_1001`），创建软件时生成，便于轮换与追踪 |
| `public_b` | TEXT | 是 | NULL | 该软件公钥 B_i（PEM 文本），发卡时写入 K 码下发，软件不预置 |
| `private_b_path` | VARCHAR(191) | 是 | NULL | 该软件私钥 B_i 相对路径（Web 根外，如 `../keys/private_b_1001.pem`） |
| `status` | TINYINT UNSIGNED | 否 | 1 | 1=启用 0=禁用 |
| `created_at` / `updated_at` | INT UNSIGNED | 否 | 0 | 时间戳 |

```sql
CREATE TABLE `lc_softwares` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name` VARCHAR(128) NOT NULL COMMENT '软件名称',
  `identifier` VARCHAR(64) NOT NULL COMMENT '软件唯一标识',
  `default_mode` VARCHAR(16) NOT NULL DEFAULT 'time' COMMENT 'time时效 times次数',
  `default_days` INT UNSIGNED NOT NULL DEFAULT 30 COMMENT '时效默认天数',
  `default_times` INT UNSIGNED NOT NULL DEFAULT 100 COMMENT '次数默认次数',
  `default_config` TEXT NULL COMMENT '默认配置JSON',
  `b_key_id` VARCHAR(64) NOT NULL COMMENT '软件B_i密钥标识',
  `public_b` TEXT NULL COMMENT '软件公钥B_i(PEM)，随该软件K码下发',
  `private_b_path` VARCHAR(191) DEFAULT NULL COMMENT '软件私钥B_i路径(Web根外)',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
  `created_at` INT UNSIGNED NOT NULL DEFAULT 0,
  `updated_at` INT UNSIGNED NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_identifier` (`identifier`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='软件表';
```

> 全局一对密钥 A 在安装时生成（私钥 A 落盘 `keys/private_a.pem`，公钥 A 内置所有软件）；**每个软件的 B_i 密钥对在创建该软件时自动生成**：私钥 B_i 落盘到 `private_b_path`（Web 根外），公钥 B_i 以 PEM 文本存入 `public_b`，发卡时写入 K 码下发。轮换某软件 B_i 时更新这三个字段并重发该软件 K 码即可，软件内置公钥 A 不变。

### 3.4 授权票据表 `lc_tickets`

次数型每次消费生成一张短时效一次性票据。

```sql
CREATE TABLE `lc_tickets` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `ticket` CHAR(64) NOT NULL COMMENT '票据令牌',
  `card_id` VARCHAR(64) NOT NULL COMMENT '卡号',
```

### 3.8 密钥文件布局

```
keys/                                    # Web 根之外，目录权限最小化
├── private_a.pem                        # 全局私钥 A，0600，签发/重签 K 码
├── public_a.pem                         # 全局公钥 A，内置于所有软件
└── private_b_{software_id}.pem          # 每个软件一把私钥 B_i，0600，加密该软件业务包
```

- 全局 A 只有一对，`private_a.pem` 在安装时生成一次。
- 每个软件一对 B_i：`private_b_{software_id}.pem` 随软件创建生成，路径写入 `lc_softwares.private_b_path`；文件名由系统生成，与软件 ID 绑定。
- 公钥 B_i 不落盘为公共文件，以 PEM 文本存于 `lc_softwares.public_b`，并在发卡时写入 K 码载荷 `b` 字段下发给软件；软件**不预置公钥 B**。

## 4. 表关系（ER 概述）

```
lc_softwares (1) ──< (N) lc_cards        软件拥有多张卡
lc_cards      (1) ──< (N) lc_tickets     卡产生多条票据
lc_cards      (1) ──< (N) lc_request_logs 卡产生多条请求日志（通过 card_id 关联，弱关联）
lc_admins     (1) ──< (N) lc_admin_logs   管理员产生多条操作日志
lc_settings   独立键值表
```

- 外键关系在应用层维护（不建物理外键，便于分表与导入导出）；`card_id` 为业务关联键。
- 日志表与卡表为弱关联：即使卡被清理，日志仍保留用于审计。

## 5. 字段级业务规则校验

| 表.字段 | 规则 |
|---|---|
| `cards.mode=time` | `expire_at>0`，`total_times/remain/used` 应为 0 |
| `cards.mode=times` | `total_times>0`，`remain<=total_times`，`expire_at` 应为 0 |
| `cards.remain` | 仅通过原子 UPDATE 递减，后台"改次数"为管理员显式覆盖并记录日志 |
| `cards.custom_config` | 非空时必须是合法 JSON，覆盖 `softwares.default_config` |
| `tickets.expire_at` | 创建时 = now + `ticket_ttl` |
| `request_logs.nonce` | 全局唯一；重复即判定重放 |
| `admins.password_hash` | 由 `password_hash` 生成，`password_verify` 校验 |

|---|---|---|
| `lc_request_logs` | 快（每次请求） | 保留近 N 个月（如 6 个月），更早归档导出后清理；`idx_time` 支撑清理 |
| `lc_tickets` | 中 | 清理 `expire_at < now - 86400` 的记录 |
| `lc_admin_logs` | 慢 | 长期保留 |
| `lc_cards` / `lc_softwares` | 慢 | 长期保留 |

归档 SQL 示例（云服务器可加定时任务；虚拟主机在后台提供手动触发）：

```sql
DELETE FROM `lc_request_logs` WHERE `created_at` < UNIX_TIMESTAMP() - 15552000; -- 180天
DELETE FROM `lc_tickets` WHERE `expire_at` < UNIX_TIMESTAMP() - 86400;           -- 过期1天后
```
